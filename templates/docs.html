How SpamGuard Is Made & How It Works

A concise technical overview of the classical NLP pipeline, machine learning modeling, and real-time inference workflow.

Phase 1

1. How It Is Made

SpamGuard was engineered as a pure classical Machine Learning solution without heavy neural networks or third-party cloud APIs. The system was constructed in four core stages:

A. Dataset Ingestion

Trained on the UCI Machine Learning Repository — SMS Spam Collection (5,574 messages: 4,827 legitimate Ham and 747 unsolicited Spam). Stratified 80/20 train/test splitting was applied to maintain natural class proportions.

B. Domain-Specific Text Preprocessing

Raw SMS text is cleaned using a custom regex normalization pipeline in src/preprocessing.py: lowercasing, converting URLs to urladdr, phone numbers to numtoken, currencies (£, $) to currsym, and stripping punctuation. Common stopwords are intentionally retained because words like "free", "win", and "call" are vital spam discriminators.

C. TF-IDF Feature Engineering

A TfidfVectorizer is fitted strictly on the training set to prevent data leakage. It extracts 11,703 unigram and bigram features with sublinear term-frequency scaling (sublinear_tf=True), which dampens the weight of repeated words while prioritizing distinctive bigrams like "cash prize" and "call now".

D. Model Benchmarking & Serialization

Three classical models were trained and benchmarked under identical conditions: Multinomial Naive Bayes, Logistic Regression, and Linear SVM. Linear SVM demonstrated the highest overall Spam F1-score (0.9726) and recall (95.30%), and was persisted with joblib alongside the vectorizer for fast production loading.

Phase 2

2. How It Works (Runtime Workflow)

When a user submits an SMS message, the application processes it through an end-to-end 5-step pipeline in under 2 milliseconds:

01
Input Validation

FastAPI validates the payload via Pydantic, enforcing non-empty input and a 1,600-character safety limit.

02
Token Normalization

The message is normalized using clean_text(), turning raw links, numbers, and symbols into standardized NLP tokens.

03
Sparse Vectorization

The saved TF-IDF vectorizer transforms the normalized text into a 11,703-dimensional sparse feature vector.

04
Decision Boundary Calculation

The Linear SVM computes the signed distance (margin) from the separating hyperplane: positive values indicate Spam, negative values indicate legitimate Ham.

05
Dynamic JSON Response & UI Render

FastAPI returns the classification label, visual risk rating (High/Low Risk), decision margin score, and analysis explanation to the frontend without reloading the page.

Why Linear SVM was selected:

Linear SVM achieved the highest F1-score (0.9726) and caught 142 out of 149 spam messages (95.3% recall) while maintaining 99.30% precision (yielding only 1 false positive out of 966 legitimate messages).
